# Импорт проектов: схема БД 9

Актуальность: 21 ноября 2026 года. SQL приложения реализован в `ElData/ElDBScheme.py`,
механизм SQLite и транзакций — в `ElData/ElDBConnect.py`;
`ElPluginMgr/repository.py` проверяет данные и делегирует сохранение,
управление плагинами — в `ElPluginMgr/manager.py`. [Порядок работы](plugin-runtime.md).

Один проект использует один текущий плагин и может импортироваться многократно. Время последнего успешного импорта хранится в PROJECTS.last_imported_at (UTC); неудачные попытки его не изменяют. Плагину передаётся только source_uri. Название, описание, внешний ID, свойства и компоненты возвращает плагин. При замене или обновлении плагина проект получает needs_reload=1; после успешного импорта — 0. Эти действия реализованы менеджером и `ProjectRepository`; миграция создаёт структуру хранения.

Система плагина (например, KiCad) объявляется самим плагином в метаданных. Данные проекта и источника объединены в PROJECTS. Таблиц PROJECT_SOURCES и PROJECT_IMPORTS нет. Страницы/листы отдельными полями не хранятся. Старое schematic_path преобразуется в source_uri: существующий URI сохраняется, локальный путь становится file URI, относительный путь разрешается от папки базы. Преобразование не открывает исходные файлы.

## PLUGINS

Версия 6 добавляет таблицу метаданных плагинов: `id`, `plugin_type`, `name`,
`version`, `api_version`, `system_id`, `system_name`, `description`, `author`,

`shipment_tracking`. Их объявляет плагин в манифесте и `get_plugin_type()`;
установщик сверяет значения до регистрации. Импорт проекта допускает только
`project_import`.

Полные типы столбцов и ограничения: [структура БД](database-plugins-and-parts.md#plugins).

## PROJECT_COMPONENTS

Одна строка — одна физическая позиция. Количество одинаковых деталей вычисляется группировкой. Пара (project_id, external_id) уникальна. Описание номинала хранится без потери исходного текста.

| Имя | Тип | Описание |
|---|---|---|
| id | INTEGER PK | ID позиции. |
| project_id | INTEGER FK | Ссылка на PROJECTS.id. |
| external_id | TEXT | Устойчивый идентификатор экземпляра, предоставленный плагином. |
| reference | TEXT | Обозначение, например R1, U6. |
| kind | TEXT | Категория компонента; по умолчанию unknown. |
| value_raw | TEXT | Исходное значение или модель; по умолчанию пустая строка. |
| nominal_value | TEXT | Нормализованное число десятичной строкой, например 0.002. |
| nominal_unit | TEXT | Единица нормализованного номинала, например ohm, F, H. |
| model | TEXT | Модель детали. |
| symbol_id | TEXT | Идентификатор библиотечного символа. |
| footprint | TEXT | Полное имя посадочного места. |
| description | TEXT | Описание компонента. |
| in_bom | INTEGER | Включён в перечень деталей: 0/1, по умолчанию 1. |
| on_board | INTEGER | Размещается на плате: 0/1, по умолчанию 1. |

## Связи и миграция

PROJECTS → PROJECT_COMPONENTS → PROJECT_COMPONENT_MATCHES и PARTS → PROJECT_COMPONENT_MATCHES имеют ON DELETE CASCADE. Есть индекс PROJECT_COMPONENT_MATCHES(part_id); уникальный индекс (project_id, external_id) также обслуживает поиск компонентов проекта. Каскады при прямой работе SQL требуют PRAGMA foreign_keys=ON. `DBScheme` включает внешние ключи перед транзакцией записи или удаления проекта, вызванной через `ProjectRepository`. Обычный коннектор не включает их при открытии соединения; удаление складской детали явно удаляет её сопоставления.

Удаление детали через PartsDB явно удаляет её сопоставления одной транзакцией, сохраняя позиции проектов. Интерфейс перед удалением предупреждает о количестве сопоставлений. При отмене ничего не меняется. Защита старых связей EL_BY_PROJECT сохранена.

Миграция 4 → 5 сохраняет ID, имена и описания старых проектов, счётчик AUTOINCREMENT и старые связи EL_BY_PROJECT. Перестроение PROJECTS, создание таблиц и запись версии атомарны. При ошибке изменения откатываются. Повторное выполнение безопасно. Структура результата и сериализация JSON проверяются протоколом и repository; поддержку URI определяет плагин. SQL этих проверок не выполняет.


## Повторный импорт и удаление проекта

Проект и все позиции сохраняются одной транзакцией. Позиции обновляются по
`(project_id, external_id)` с сохранением внутренних ID и выбранных сопоставлений.
Изменение требований выставляет `needs_review=1`; переименование обозначения
с тем же внешним ID само по себе не сбрасывает связь со складом.
Исчезнувшие позиции удаляются каскадно вместе со своими сопоставлениями.
При ошибке запись откатывается вместе с датой импорта и `needs_reload`.

Удаление проекта также удаляет его старые строки `EL_BY_PROJECT`; карточки
`PARTS` сохраняются. Пути к установленным окружениям хранятся в файловом реестре,
а их типы и метаданные — в таблице `PLUGINS`.
