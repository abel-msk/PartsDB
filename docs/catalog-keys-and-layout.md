# Ключевые колонки, базовые типы и отображение списков

Актуальность: 20.11.2026. Схема БД: **7**. Описание относится к приложению; личная база склада при разработке не изменяется.

## Базовые типы

`BASIC_TYPES` — отдельный справочник, заполняемый при создании базы и миграции 6 → 7.
Поля: `id` (стабильный первичный ключ), `name` (уникальное английское название),
`designator` (буквенное позиционное обозначение на схеме), `icon` (пока NULL, резерв).
Название не переводится при смене языка интерфейса. Позиционное обозначение —
буквенный префикс вроде `R` или `C`, графическое изображение символа здесь не хранится.

Основа справочника — [KiCad Library Conventions, S6.1](https://klc.kicad.org/symbol/s6/s6.1/).
Это принятый в приложении набор, а не заявление о единственном универсальном стандарте обозначений.

`Miscellaneous` соответствует «разное», его ID — 1. `TYPES.basic_type_id` —
обязательная ссылка на справочник, по умолчанию 1. В форме добавления секции
задаются название и базовый тип. Начальный выбор берётся от родительской секции;
для корневой секции — `Miscellaneous`. Команда добавления секции создаёт соседа
выбранной секции, команда добавления дочерней — её потомка. При отсутствии выбора
добавляется корневая секция. Переименование позволяет изменить и базовый тип.
Изменение родителя не переписывает базовые типы уже существующих потомков.

При миграции известные русские и английские названия секций сопоставляются
со справочником; например, `Резистор`, `Конденсатор`, `Транзистр`. Остальные секции
наследуют распознанный тип предка, а без такого предка получают `Miscellaneous`.
Неподходящий результат можно исправить через переименование секции.

## Ключевые колонки

`HEADERS.is_key` хранит свойство **«Ключевое значение»**:

- `1` — ключевая колонка;
- `0` — обычная колонка;
- `NULL` — выбор по базовому типу: `value` для `Resistor` и `Capacitor`,
  `part_num` для остальных.

Несколько колонок одной секции могут быть ключевыми. Флажки настраиваются в форме
редактирования заголовков. Необходимо оставить хотя бы одну ключевую колонку.
Настройки заголовков наследуются от предков по существующим правилам; явные
настройки `is_key` также наследуются. Изменение ширины колонки само по себе
не превращает выбор по умолчанию в явную настройку. Команда распространения
заголовков копирует выбранные ключи потомкам вместе с остальными свойствами.

В таблице каталога заголовки ключевых колонок жирные, остальные обычные.
При добавлении детали открывается окно **«Введите номинал детали»** с отдельным
полем для каждой ключевой колонки. Подписи берутся из отображаемых названий
заголовков, порядок — из их настроенного порядка. Все поля обязательны.
`part_num` может оставаться пустым, если он не входит в ключевые колонки.
После добавления таблица пересортировывается по текущей колонке и направлению.
Новая деталь становится единственной выделенной строкой; при необходимости
таблица прокручивается к ней, в том числе при совпадении ключей с другой деталью.
Отмена не создаёт деталь. Единицы измерения и прочие свойства продолжают
редактироваться в таблице, если они отдельно не выбраны ключевыми.

Выбранные ключи предназначены для последующего сопоставления с компонентами
проектов. Автоматический алгоритм сопоставления в это изменение не входит;
существующие подтверждённые связи сохраняются.

## Общий вид каталога и проектов

`ElTwoLineDelegate.TwoLineDelegate` используется деревом каталога и списком проектов.
Верхняя строка — название; нижняя — базовый тип секции либо тип/название плагина
проекта по существующим правилам. Размер строки, отступы и цвета общие.

Параметры записываются в конфиг приложения, секция `list_fonts`:

```yaml
list_fonts:
  title_size: 16
  subtitle_size: 10
  title_color: palette
  subtitle_color: gray
```

Размеры заданы в пикселях. `palette` использует цвет текста текущей темы;
остальные цвета задаются в формате QColor, например `gray` или `'#808080'`.
При выделении обе строки используют цвет выделенного текста темы.
Изменение через меню настроек будет добавлено отдельно.

## Ширины таблиц проектов

`PROJECT_COLUMN_WIDTHS` хранит ширины в пикселях: `table_name`, `field_name`, `width`.
Составной первичный ключ — `(table_name, field_name)`, `width > 0`.
Настройки общие для проектов в текущей БД, раздельные для таблиц
`project_components` (загруженные детали) и `project_unmatched` (несопоставленные).
Поля идентифицируются стабильными именами, а не переведёнными заголовками.

Ширины сохраняются после изменения пользователем мышью. Автоматическое
растяжение и загрузка проекта их не перезаписывают. До первого изменения
базовая ширина каждой колонки — 100 пикселей.

Если доступная ширина больше суммы сохранённых ширин, все колонки увеличиваются
в одинаковое число раз: `ширина = сохранённая × доступная / сумма сохранённых`.
При сужении они возвращаются к сохранённым размерам, после чего появляется
горизонтальная прокрутка. Переключение проекта сохраняет настройки;
переключение базы загружает настройки выбранной базы.

## Миграция и слои приложения

Миграция 6 → 7 создаёт справочник и таблицу ширин, добавляет `basic_type_id`
и `is_key`, сохраняя детали, заголовки и проектные сопоставления.
SQL и миграция находятся в `ElData/ElDBScheme.py`; новые операции каталога
проходят через `ElData/ElDBDataParts.py`, ширины проектов — через
`ElData/ElDBDataProj.py`. Константы отображения — в `ElConstants.py`.
