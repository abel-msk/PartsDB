# Ключевые колонки, базовые типы и отображение списков

Актуальность: 21.11.2026. Схема БД: **11**. Описание относится к приложению; личная база склада при разработке не изменяется.

## Базовые типы в интерфейсе

Полный состав справочника, поля и связи приведены в [BASIC_TYPES](database-schema.md#basic_types).
Редактирование справочников описано в [инструкции окна](units-and-project-applications.md).

В форме добавления секции задаются название и базовый тип. Начальный выбор берётся
от родительской секции, для корня — «разное». Добавление секции создаёт соседа
выбранной секции, добавление дочерней — её потомка. При отсутствии выбора создаётся
корневая секция. Переименование позволяет изменить и базовый тип. Изменение родителя
не переписывает базовые типы уже существующих потомков.

## Ключевые колонки

Свойство «Ключевое значение» и его значения описаны в [HEADERS](database-schema.md#headers).

Несколько колонок одной секции могут быть ключевыми. Флажки настраиваются в форме
редактирования заголовков. Необходимо оставить хотя бы одну ключевую колонку.
Настройки заголовков наследуются от предков по существующим правилам; явные
настройки `is_key` также наследуются. Изменение ширины колонки само по себе
не превращает выбор по умолчанию в явную настройку. Команда распространения
заголовков копирует выбранные ключи потомкам вместе с остальными свойствами.

В таблице каталога заголовки ключевых колонок жирные, остальные обычные.
При добавлении детали открывается окно **«Введите номинал детали»** с отдельным
полем для каждой ключевой колонки. Подписи берутся из отображаемых названий
заголовков, порядок — из их настроенного порядка. Все поля обязательны.
`part_num` может оставаться пустым, если он не входит в ключевые колонки.
После добавления таблица пересортировывается по текущей колонке и направлению.
Новая деталь становится единственной выделенной строкой; при необходимости
таблица прокручивается к ней, в том числе при совпадении ключей с другой деталью.
Отмена не создаёт деталь. Единицы измерения и прочие свойства продолжают
редактироваться в таблице, если они отдельно не выбраны ключевыми.

Выбранные видимые ключи используются `ElPartsMatching.py` для автоматического
поиска кандидатов по Value, Kind, единицам СИ и способу монтажа. В таблице проекта
показывается кнопка статуса `YES`/`NO`; текст первого найденного ключа доступен
в её подсказке, внутренние ID хранятся скрыто.
Подтверждённые связи сохраняются отдельно. [Правила сопоставления](parts-matching.md).

## Общий вид каталога и проектов

`ElTwoLineDelegate.TwoLineDelegate` используется деревом каталога и списком проектов.
Верхняя строка — название; нижняя — базовый тип секции либо тип/название плагина
проекта по существующим правилам. Размер строки, отступы и цвета общие.

Параметры записываются в конфиг приложения, секция `list_fonts`:

```yaml
list_fonts:
  title_size: 16
  subtitle_size: 10
  title_color: palette
  subtitle_color: gray
```

Размеры заданы в пикселях. `palette` использует цвет текста текущей темы;
остальные цвета задаются в формате QColor, например `gray` или `'#808080'`.
При выделении обе строки используют цвет выделенного текста темы.
Изменение через меню настроек будет добавлено отдельно.

## Ширины таблиц проектов

Структура хранения: [PROJECT_COLUMN_WIDTHS](database-schema.md#project_column_widths).
Настройки общие для проектов текущей БД и раздельные для двух таблиц. Поля
идентифицируются стабильными именами, а не переведёнными заголовками.

Ширины сохраняются после изменения пользователем мышью. Автоматическое
растяжение и загрузка проекта их не перезаписывают. До первого изменения
базовая ширина каждой колонки — 100 пикселей.

Если доступная ширина больше суммы сохранённых ширин, все колонки увеличиваются
в одинаковое число раз: `ширина = сохранённая × доступная / сумма сохранённых`.
При сужении они возвращаются к сохранённым размерам, после чего появляется
горизонтальная прокрутка. Переключение проекта сохраняет настройки;
переключение базы загружает настройки выбранной базы.

## Слои приложения

Новые операции каталога проходят через `ElData/ElDBDataParts.py`, ширины проектов —
через `ElData/ElDBDataProj.py`. Константы отображения — в `ElConstants.py`.
[История и механизм миграций](database-migrations.md) описаны отдельно от интерфейса.
