# Сопоставление компонентов проекта с каталогом

[English version](parts-matching.en.md)

Актуальность: 24 ноября 2026 года. Алгоритм находится в
[ElPartsMatching.py](../ElPartsMatching.py), класс `PartsMatching`.

Пошаговое описание с таблицами совпадений и отказов: [алгоритм с примерами](parts-matching-algorithm-examples.md).

## Использование автоматического сопоставления

Автоматический поиск подбирает карточки каталога PartsDB для компонентов схемы,
полученных через плагин импорта. Например, импортированный из KiCad
резистор `R1` со значением `10K` может получить кандидата из раздела резисторов
с ключами `value=10` и `units=кОм`, если подходит способ монтажа.

### Подготовка

- Подключите и включите импортёр через **Настройки → Плагины… → Установить из файла**.
  Выберите пакет `.whl`; [подробности установки](plugins-ui.md#менеджер-плагинов).
- На вкладке **Проекты** добавьте проект через установленный импортёр, проверьте
  предпросмотр и сохраните полученные из схемы компоненты.
- Заполните карточки деталей в каталоге. Для разделов укажите подходящий базовый
  тип и выберите ключевые колонки в редакторе заголовков. Поиск использует видимые
  ключи; например, для резисторов это могут быть номинал и единица измерения.
  [Настройка ключей и базовых типов](catalog-keys-and-layout.md).

### Поиск и сохранение

1. Выберите импортированный проект на вкладке **Проекты**.
2. Нажмите **Link Part / Сопоставить деталь**. Импорт и открытие проекта сами
   по себе поиск не запускают. Журнал показывает прогресс и найденные варианты
   либо «Не найдено» для каждой группы компонентов.
3. Дождитесь завершения и проверьте результаты. `YES` в таблице означает, что
   найдены кандидаты или уже есть подтверждённая связь; этот статус сам по себе
   не означает, что найденный кандидат записан в базу.
4. Нажмите **Save / Сохранить** в журнале. Запишутся однозначные совпадения
   для компонентов без ранее подтверждённой связи. Если кандидатов несколько,
   ни один из них не выбирается автоматически. Существующие связи сохраняются.
   После успешного сохранения журнал закрывается.
5. Для остальных компонентов используйте [ручной выбор в правой панели](#ручное-сопоставление-в-правой-панели).
   Список **Несопоставленные детали** содержит только позиции без кандидатов
   и подтверждённой связи. Компоненты с несколькими кандидатами ищите в общей
   таблице **Используемые детали**: в список несопоставленных они не попадают.

**Cancel / Отмена** закрывает журнал без записи связей и останавливает поиск,
если он ещё идёт. Кандидаты остаются в памяти; после закрытия приложения или
смены БД несохранённые результаты теряются. Подтверждённые через Save или Link
сопоставления сохраняются в базе и доступны после перезапуска.

Поиск не ограничивается деталями с признаком наличия и не проверяет достаточность
запаса. Импорт и сопоставление не меняют складские остатки.
Если кандидатов нет, проверьте исходный Value из схемы, базовый тип раздела,
видимость и состав ключей, единицы измерения и корпус. После исправления каталога
или повторного импорта изменённой схемы снова запустите **Link Part**.
[Подробные правила сравнения с примерами](parts-matching-algorithm-examples.md)
и [поведение кнопок журнала](#запуск-и-журнал).

## Входные данные и область поиска

Сопоставление использует исходную колонку `Value` компонента: `value` во входном
словаре либо `value_raw` у импортированной позиции. Поля `model` и нормализованный
`nominal` не заменяют исходное значение.

`kind` сопоставляется с именем базового типа из `BASIC_TYPES` и его алиасами.
Для стандартных категорий предусмотрены соответствия, например `ic` → Integrated
circuit, `connector` → Jack/Plug, `module` → Sub-assembly or module.
Список секций строится рекурсивным CTE от соответствующих базовых типов:
участвуют и дочерние разделы независимо от их собственного базового типа.
Имя секции не определяет её категорию. Неизвестный `kind` без соответствующего
типа или алиаса не ищется по всему каталогу.

Сравнение выполняется по колонкам, отмеченным `is_key`, с учётом наследования
настроек и порядка колонок. Скрытые колонки не используются. Наличие на складе
не ограничивает поиск: результат описывает соответствие карточке каталога.

## Значения с единицами СИ

Число с распознанной единицей или приставкой разбирается по справочникам
`SI_UNITS` и `SI_UNIT_ALIASES`: английские и русские обозначения, множители и ссылки на основную
единицу. Поддерживаются точка и запятая, micro-обозначения `u`, `µ`, `μ`,
распространённые записи сопротивлений `R`, `Ω`, `k`, `K`, `M`.
Перед поиском единицы обе стороны — исходный суффикс и обозначения справочника —
переводятся в верхний регистр. Поддерживаются также полные русские обозначения
сопротивления `кОм`, `МОм`. Если после этого несколько единиц с разными множителями
получают одно обозначение (например, `mR` и `MR`), сохраняются все интерпретации
и все соответствующие кандидаты. Подтверждённая связь автоматически не выбирается. Дополнительные обозначения
редактируются в колонке «Алиасы» окна единиц СИ. Сохранение обновляет кандидатов
открытого проекта без переимпорта. Сопоставитель не генерирует
сопротивления `кОм` или `kR` в своём коде.

Для каждой ключевой колонки допускаются:

- число с единицей в самой колонке: `100nF`;
- число в ключе и единица в отдельном ключе;
- число в ключе и единица в видимой колонке `units`;
- число в основной единице, заданной для базового типа, если отдельная единица
  не заполнена и её нельзя получить из ключей.

Размерность сравнивается отдельно, а числа приводятся к основной единице через
десятичную арифметику. Поэтому `100nF`, `0.1uF` и каталог `100` + `нФ` совпадают,
а `100` + `мкФ` или `100` + `V` не совпадают. Редактирование справочника меняет
правила следующего прохода сопоставления; жёстко заданного списка номиналов нет.

## Значения без распознанной единицы

В подходящих секциях исходное значение сравнивается с каждым видимым ключом.
Для `part_num` обе строки обрезаются до длины кратчайшей и сравниваются без
учёта регистра. Пустые строки не совпадают. Прочие ключи сравниваются целиком.
Пробелы по краям игнорируются.
Для полностью числовых значений сравниваются числа: `0,3` равно `0.3`.
`AMS1117-3.3` совпадает с `AMS1117-3.3-extra` в `part_num`;
`AMS1117` также совпадает с `AMS1117-3.3`. Это поиск кандидатов, а не гарантия
электрической взаимозаменяемости.

## Способ монтажа

Последним шагом и для числовой, и для текстовой ветки проверяются `Footprint`
и видимый `package` карточки каталога:

| Текст | Принятый монтаж |
|---|---|
| Содержит SMD | SMD |
| Содержит THT; также поддержаны ТНТ/TNT | THT |
| Заполнен, явного SMD/THT нет: `0805`, `SOT-23` | SMD |
| Пустой `package` | Проверка корпуса пропускается |
| Пустой `Footprint` | Ограничение со стороны источника отсутствует |

Таким образом, `Capacitor_THT:...` не совпадает с карточкой `package=0805`,
а `Capacitor_SMD:...` совпадает. Это правило применяется к тексту обоих полей;
корпус без метки не анализируется по геометрии и считается SMD.

## Результат и таблицы проекта

`findCandidates(component)` возвращает все найденные `CatalogMatch` в порядке
ID карточек каталога. Класс данных находится в
[ElData/ElDBDataParts.py](../ElData/ElDBDataParts.py):

- `part_id` — ссылка на карточку каталога;
- `type_id` — ссылка на её раздел;
- `key_text` — текст первой совпавшей ключевой колонки в настроенном порядке;
- `matched_fields` — имена совпавших ключевых колонок.

В `prj_parts_all` (Used parts) и `no_matched_tbl` колонка **Статус сопоставления**
содержит кнопку: зелёную `YES`, если есть кандидаты или подтверждённая связь,
и красную `NO`, если нет ни того, ни другого. В `no_matched_tbl` попадают только
строки `NO`. Нажатие кнопки выбирает компонент и обновляет селекторы правой
панели через `ProjWindow.matchingRequested(component_id)`; само нажатие не меняет базу.

`key_text` первого кандидата или подтверждённой карточки доступен в подсказке
кнопки и `MATCHING_LABEL_ROLE`. ID позиции хранится в `Qt.UserRole`, ID кандидатов —
в `MATCHING_CANDIDATES_ROLE`, статус — в `MATCHING_STATUS_ROLE`.
Полные результаты доступны в `ProjWindow.matchingCandidates`.
До нажатия **Save / Сохранить** в журнале автоматические результаты хранятся
только в памяти. Save подтверждает только однозначные совпадения;
[порядок сохранения](#запуск-и-журнал) описан ниже.
Существующие подтверждённые связи не заменяются автоматически. Поиск не изменяет
карточки, остатки или таблицы связей; SQL выполняется только в `ElData/ElDBScheme.py`
через функции `ElData/ElDBDataParts.py`. Новая таблица или миграция не требуются.

## Ручное сопоставление в правой панели

Ручная привязка выполняется на вкладке **Проекты**, без перехода в каталог.
Кнопка **Link Part / Сопоставить деталь** запускает автоматический поиск кандидатов,
а **Link / Привязать** в правой панели сохраняет выбранную пользователем связь.
Для ручного выбора предварительный автоматический поиск не требуется.

1. Выберите проект, затем строку компонента в **Used Parts / Используемые детали**
   (`prj_parts_all`) или **Unmatched parts / Несопоставленные детали** (`no_matched_tbl`).
   Достаточно выбрать любую ячейку нужной строки. Можно также нажать её кнопку `YES` или `NO`.
2. В правой панели выберите **Sections / Разделы** (`section_list`). Разделы показаны
   полным путём, например `Резисторы / SMD`. В **Parts / Детали** (`parts_list`)
   появятся карточки этого раздела и его дочерних разделов.
3. Выберите карточку в списке деталей. Её подпись состоит из значений видимых
   ключевых колонок в настроенном порядке, объединённых через пробел.
   Например, при ключах «Номинал» и «Единица» подпись может быть `10 кОм`.
   Список включает карточки каталога независимо от наличия на складе.
4. Проверьте **Properties / Свойства** (`prop_list`). Для каждой видимой колонки
   выбранной карточки выводится одна строка стандартного списка в формате
   `Заголовок: значение`. Скрытые колонки и внутренние ID не показываются.
   Порядок и названия берутся из настроек раздела выбранной карточки.
5. Нажмите **Link / Привязать**. Если у компонента уже есть подтверждённая связь
   или найденные автоматические кандидаты, подтвердите замену в диалоге.
   Ответ «Нет» сохраняет прежнее сопоставление.

Если компонент проекта или карточка каталога не выбраны, приложение предупреждает:
«Сначала выберите компонент проекта и деталь каталога». Связь при этом не сохраняется.

При выборе другой строки проекта все селекторы правой панели синхронизируются:

- при наличии подтверждённой связи показывается связанная карточка;
- если подтверждённой связи нет, показывается первый найденный кандидат;
- если нет ни связи, ни кандидатов, выбор раздела и оба списка очищаются.

Показ кандидата в панели ещё не подтверждает связь. После нажатия **Привязать**
связь записывается в `PROJECT_COMPONENT_MATCHES`, признак перепроверки сбрасывается,
обе таблицы обновляются, а компонент выбирается в общей таблице.
Он исчезает из списка несопоставленных. Карточка каталога и её остаток не меняются.
Ручной выбор позволяет указать карточку, которую автоматический алгоритм не нашёл;
при нажатии **Привязать** проверки Value, Kind и способа монтажа повторно не выполняются.

Ширину правой панели можно менять разделителем. При закрытии окна она сохраняется
в конфиге как `window.project_right_width` и восстанавливается при открытии вкладки
проекта. При смене базы данных выбранный компонент и списки правой панели очищаются.

Для удаления связи используйте контекстное меню строки в общей таблице:
**Удалить сопоставление со складом**. Дополнительно доступен прежний способ привязки:
выберите карточку на вкладке каталога и вызовите **Сопоставить с выбранной деталью
склада** в контекстном меню компонента проекта.

## Проверка

```sh
python -m unittest tests.test_parts_matching tests.test_project_selector -v
./build.sh -t
```

Тесты используют временные каталоги: СИ и приставки, раздельные ключи, скрытые
колонки, алиасы, дочерние секции, точное совпадение моделей, SMD/THT и ссылки
в модели таблицы. `tests/test_project_selector.py` проверяет ручную привязку,
подтверждение замены, отсутствие выбора, синхронизацию селекторов, смену БД,
отмену смены раздела в редакторе колонок и сохранение ширины панели.
После успешного полного прогона `build.sh` выполняет штатную
очистку временной БД и тестовых бэкапов; при ошибке — ротацию с сохранением
диагностических данных.


## Исправление несовпадений резисторов

В настроенной тестовой БД резисторы имеют ключи `value` и `units`, например
`1` + `кОм`. Ранее алиасы включали `k`, `kR`, `kΩ`, но не полное `кОм`,
поэтому такие карточки не проходили проверку единицы. Добавлен русский суффикс
`Ом` для приставок и сравнение в верхнем регистре.

На временной копии тестовой БД после миграции 10 → 11 все 11 резисторов проекта
`SMHome_UniversalRound_ESP32_C3_Mini_v4` получили кандидатов. У другого,
ранее импортированного проекта позиции `51k` и `0,002R` остались без кандидатов:
в каталоге тестовой БД нет таких значений. Это отсутствие номиналов,
а не ошибка проверки корпуса.

## Запуск и журнал

Автоматический проход запускается только кнопкой **Link Part / Сопоставить деталь**.
Загрузка, импорт, смена проекта и перерисовка таблиц поиск не запускают.
Окно `ElLogWnd` показывает прогресс по группам PROJECT_COMPONENTS и строку для
каждой группы: обозначения, Value, количество, найденные ключи либо «Не найдено».
После завершения поиска в окне журнала доступны **Cancel / Отмена** и
**Save / Сохранить**:

- **Save** записывает в `PROJECT_COMPONENT_MATCHES` только результаты, у которых
  найден ровно один кандидат и ещё нет подтверждённой связи. Новые связи получают
  `needs_review=0`. Уже подтверждённые связи сохраняются без изменений, включая
  их признак перепроверки. Неоднозначные результаты и позиции без кандидатов
  пропускаются: для них используйте ручной выбор в правой панели. После успешной
  записи обновляются таблицы проекта и закрывается журнал.
- **Cancel** закрывает журнал без записи сопоставлений. Если поиск ещё идёт,
  он прекращается. Уже вычисленные кандидаты остаются в памяти до смены БД
  или закрытия приложения; подтвердить нужную карточку можно вручную.

**Save** недоступна во время поиска и после ошибки или прерывания прохода.
Сохранение выполняется одной транзакцией: при ошибке ни одна новая связь
не записывается, окно остаётся открытым и показывает сообщение об ошибке.
Если после поиска изменились позиции проекта или активная БД, устаревшие
результаты сохранить нельзя — запустите поиск заново.

Повторный запуск заново проверяет каталог. При смене БД результаты в памяти
сбрасываются; после изменения единиц нужно снова нажать **Link Part**.
Сам поиск не создаёт подтверждённых связей: для записи нужна **Save** в журнале
или **Link / Привязать** для выбранной карточки в правой панели.
