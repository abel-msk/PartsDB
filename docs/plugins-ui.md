# Интерфейс плагинов и проектов

Актуальность: 21 ноября 2026 года. Менеджер, запуск импорта, предпросмотр,
сохранение и ручное сопоставление подключены к интерфейсу.

Порядок работы: [Установка и запуск импортёров](plugin-runtime.md).
API: [Архитектура плагинов](plugin-architecture-and-api.md).
Схема: [Импорт проектов](database-migrations.md).

## Менеджер плагинов

Открывается через **Настройки → Плагины…**. Исходная форма —
`qt/ElPluginsWnd.ui`, поведение — `ElPluginsDialog.py`, тексты RU/EN —
`pluginsDialogTexts()` в `ElWindowTexts.py`.

| Элемент | Действие |
|---|---|
| Установить из файла | Выбор wheel, показ метаданных, установка или обновление |
| Список плагинов | Название и функциональный тип; справа описание, автор, тип, система и версия |
| Включён | Разрешает или запрещает новые запуски импортёра |
| Удалить | Удаляет установку после подтверждения; данные проектов сохраняются |
| Журнал | Показывает журнал текущего окружения |
| Настройки | Отключено: у API 1 нет декларативной схемы настроек |
| Путь к приложению / Параметры | Настройки внешней программы для открытия проектов; `{file}` заменяется путём проекта |
| Закрыть | Сохраняет настройки запуска и закрывает окно; Escape и системная кнопка также работают |

При установке нового ID того же типа и той же системы можно заменить один из имеющихся
импортёров либо оставить оба. Установка того же ID обновляет существующий плагин.
Установка и удаление — отдельные завершённые операции, закрытие окна их не отменяет.

После установки плагин автоматически выбирается в списке, и справа заполняется
его карточка. Список и карточка читаются из таблицы `PLUGINS` текущей БД через
`PluginDataStore` и `PluginData` в `ElData/ElDBDataPlagins.py`. Перед чтением
менеджер синхронизирует таблицу с реестром установленных окружений. Сам SQL
находится в `ElData/ElDBScheme.py`; форма не выполняет запросы напрямую.

Отключённые плагины остаются в списке. Повторное открытие окна восстанавливает
их сохранённое состояние. Обновление списка и смена языка сохраняют выбранный
плагин; подсказка строки содержит ID, версию и описание. Пустой список очищает
карточку и отключает действия над выбранным плагином. Ошибка установки сохраняет
прежнюю карточку и выводится в строке состояния и отдельном сообщении.

## Вкладка проектов

`ProjList` читает карточки из `PROJECTS`. Выбор проекта заполняет имя, описание,
дату последнего успешного импорта и таблицы позиций. Кнопки подключены к
`ProjectImports` в `ElPluginMgr/ElProjectImports.py`:

| Кнопка | Действие |
|---|---|
| Добавить проект | Выбор включённого импортёра и файла/URI, чтение, предпросмотр |
| Обновить данные | Повторный импорт существующего источника и предпросмотр изменений |
| Удалить проект | После подтверждения удаляет проект и его связи, сохраняя склад |

Чтение выполняется в фоне, без блокировки обработки событий Qt. При импорте
доступна отмена. При подготовке окружения установки кнопка отмены отсутствует.
Запись БД начинается только после **Сохранить** в предпросмотре.

## Предпросмотр

`ImportPreview` показывает количество позиций и число добавленных, изменённых
и удалённых. Таблица содержит состояние изменения, обозначение, категорию,
исходное значение, посадочное место, флаги BOM и DNP. Исчезнувшие позиции видны
как удалённые. Предупреждения плагина выводятся отдельным текстовым блоком.

**Сохранить** передаёт данные в `ProjectRepository`; **Отмена** оставляет прежний
проект. Ошибка чтения, отмена или неудачная транзакция не заменяют сохранённые данные.

## Таблицы компонентов и склад

Кнопка **Link Part** запускает поиск кандидатов по [правилам сопоставления](parts-matching.md).
По завершении в журнале нажмите **Save / Сохранить**, чтобы записать однозначные
совпадения и закрыть окно. Уже подтверждённые связи сохраняются без изменений;
неоднозначные результаты требуют ручного выбора. **Cancel / Отмена** закрывает
журнал без записи, прерывая поиск, если он ещё идёт. Во время поиска Save недоступна.
В колонке **Статус сопоставления** обеих таблиц стоят кнопки: зелёная `YES`,
если найдены кандидаты или есть подтверждённая связь, и красная `NO`, если нет
ни того, ни другого. Первый совпавший ключ доступен в подсказке, ссылки хранятся
в скрытых данных модели. Кандидаты не заменяют подтверждённые связи.

Основная таблица Used parts показывает все позиции. Панель **Несопоставленные
детали** (`no_matched_tbl`) содержит только строки `NO`. Выбор строки или нажатие
её кнопки `YES`/`NO` обновляет правую панель: связанную карточку, первый кандидат
либо пустой выбор, если сопоставлений нет. Сам выбор строки не меняет базу.

Для ручной привязки выберите компонент проекта, затем в правой панели раздел
**Разделы**, карточку в списке **Детали**, проверьте **Свойства** и нажмите
**Привязать / Link**. Подпись карточки объединяет видимые ключевые значения через
пробел; каждое свойство показано одной строкой стандартного списка: `Заголовок: значение`.
Если выбор не сделан, появится предупреждение. При наличии связи или кандидатов
приложение спросит о замене. Ширина панели сохраняется в конфиге.

Подробные шаги и поведение селекторов:
[ручное сопоставление в правой панели](parts-matching.md#ручное-сопоставление-в-правой-панели).

Контекстное меню компонента в общей таблице также позволяет привязать карточку,
выбранную на вкладке каталога, или **Удалить сопоставление со складом**.
Удаление сопоставления удаляет только связь выбранной позиции.

Импорт не меняет остатки. При повторном импорте сохраняются внутренние ID позиций
и их сопоставления; изменённые требования получают `needs_review=1`.

## Метаданные списка проектов

`ProjectListModel.setPlugins(plugins)` принимает полный словарь метаданных:

```python
proj_list.model.setPlugins({
    'org.partsdb.kicad': {
        'type': 'KiCad',
        'name': 'KiCad Importer',
    },
})
```

`ProjectImports.refresh_plugins()` получает данные из `PluginManager.metadata()`
при открытии окна и после закрытия менеджера. Поле `type` заполняется из
`system_name` манифеста.

Название проекта показывается шрифтом 16 px; резервные значения — `source_uri`,
затем ID проекта. Вторая строка шрифтом 10 px серого цвета содержит тип плагина,
либо его имя. Если установленного плагина нет, вторая строка пустая.

## Интерфейсы контроллеров

| Класс | Методы / сигналы |
|---|---|
| `ProjectListModel` | `setProjects`, `clear`, `setPlugins`; роли `DisplayRole`, `UserRole`, `ToolTipRole`, `TypeRole` |
| `ProjectListDelegate` | `fonts`, `sizeHint`, `paint` — две строки списка |
| `ProjList` | `load`, `setFactory`, `getSelected`, `selectByID`, `projectSelected` |
| `ProjWindow` | `refresh`, `setFactory`, `retranslate`, `loadComponents`, `matchMenu`; сигналы добавления, удаления и повторного импорта |
| `ProjectImports` | `add`, `reload`, `remove`, `import_source`, `refresh_plugins` |

При обновлении списка сохраняется выбранный ID, если проект ещё существует.
При смене базы выбор сбрасывается. Смена языка обновляет подписи, не выполняя
повторного чтения компонентов из БД и не изменяя данные проекта.


Тип (`Импорт проектов`, `Заказ деталей`, `Отслеживание посылок`) задаётся
в самом плагине и сохраняется в `PLUGINS.plugin_type`. При выборе импортёра
другие типы скрыты. Манифест, `get_plugin_type()` и ожидаемый тип операции
сверяются перед исполнением; неподходящий плагин не сохраняет результат в БД.

## Запуск приложения проекта

`d_prj_open_cmd` вызывает `ProjWindow.onOpenProject`: программа и параметры читаются
из карточки плагина в текущей БД. Запуск отделён от PartsDB. Настройки, подстановка
путей и особенности macOS: [инструкция](units-and-project-applications.md#внешнее-приложение-проекта).

## Количество и стандартное открытие файлов

Предпросмотр и таблицы проекта показывают группы с колонкой «Количество» вместо
in_bom. Данные вне BOM не сохраняются; DNP суммируются в отдельных группах.
Открытие БД, документа, приложения и источника импорта использует стандартный
QFileDialog. Собственная форма ElOpenFileDialog удалена. Ссылки на документы
можно по-прежнему добавлять перетаскиванием URL.


## Иконки базовых типов

В редакторе справочников `b_types_tbl` первая видимая колонка использует общий
`IconCellDelegate` из `ElCommonUI.py`. Изображение добавляется перетаскиванием
в ячейку, сохраняется PNG в `<data_path>/el_icons` и фиксируется в BASIC_TYPES.icon
после Save. Пустые ячейки допустимы. Cancel отбрасывает изменения и новые PNG.
[Пути, сохранение и начальная установка](units-and-project-applications.md#что-даёт-базовый-тип-секции-и-назначенная-ему-единица-си).
