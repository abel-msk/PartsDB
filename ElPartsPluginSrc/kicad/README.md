# Импортёр KiCad

Версия пакета: **0.1.0**, API **1**. Исходники: `ElPartsPluginSrc/kicad`.

Тип плагина — `PLUGIN_TYPE_IMPORT` (`project_import`), указанный в манифесте
и методе `get_plugin_type()`. При установке и запуске PartsDB сверяет тип;
плагин возвращает стандартные модели API, а сохранением управляет приложение.

Подробное поведение и пример результата: [импортёр KiCad](../../docs/kicad-importer.md).
Общий контракт: [API плагинов](../../docs/plugin-architecture-and-api.md).
Хранение результата: [единый справочник таблиц](../../docs/database-schema.md).

Основной метод — `KiCadImporter.get_components(source_uri) -> list[ImportedComponent]`.
Принимает путь или локальный `file:` URI файла `.kicad_pro` либо `.kicad_sch`.
Для проекта читает одноимённую корневую схему и рекурсивно связанные листы.
Не требует запуска KiCad, Qt, подключения к SQLite или внешних Python-зависимостей.

Из корня PartsDB:

```sh
PYTHONPATH=ElPartsPluginSrc/kicad:. python3 - <<'PY'
from partsdb_kicad import KiCadImporter

source = 'tests/input/SMHome_UniversalRound_ESP32_C3_Mini_v4/SMHome_UniversalRound_ESP32_C3_Mini_v4.kicad_pro'
components = KiCadImporter().get_components(source)
for component in components:
    print(component.reference, component.kind, component.value_raw, component.footprint)
PY
```

Одна запись соответствует одной физической позиции. Секции многосекционного
символа объединяются; повторные экземпляры листов различаются по пути UUID.
Внешний ID состоит из пути экземпляра листа и UUID символа первой секции.
Переименование обозначения не меняет ID. Служебные символы питания и библиотечные
шаблоны исключаются. Позиции с `in_bom=False`, `on_board=False` и `dnp=True`
возвращаются с исходными флагами. Приложение исключает in_bom=False и объединяет
одинаковые детали в строки с quantity; DNP группируются отдельно от обычных.

Возвращаются исходное значение, нормализованный номинал R/C/L, категория,
модель, библиотечный символ, посадочное место, описание, пользовательские
свойства и UUID секций. Категория определяется по библиотеке и имени символа,
затем по обозначению; это подсказка для сопоставления, а не проверка параметров
детали. Нераспознанный номинал остаётся `None`, исходный текст сохраняется.

`import_project(source_uri)` возвращает `ImportedProject`: название, внешний
UUID, компоненты, предупреждения и прочитанные файлы в `properties['source_files']`.
`probe(source_uri)` проверяет корневой источник; полный обход выполняется при
импорте. Отсутствующий дочерний лист, цикл, повреждённый файл, неоднозначные или
незаполненные обозначения вызывают стандартное исключение API. Частичный список
при ошибке не возвращается.

Поддерживается современный S-expression формат схем с UUID. Старые `.sch`,
HTTP/HTTPS и произвольные переменные путей листов пока не поддерживаются.
В путях листов разрешается `${KIPRJMOD}`. API предоставляет PartsDB через
`ElPartsPluginApi`; пакет плагина содержит манифест `partsdb-plugin.json`.
Установка через менеджер, запуск в отдельном процессе, предпросмотр и сохранение
в БД реализованы. Плагин также можно вызывать непосредственно из Python.
См. [инструкцию установки и запуска](../../docs/plugin-runtime.md).

## Сборка

Из корня PartsDB:

```sh
./build.sh -p
```

Создаёт `dist/plugins/partsdb_kicad-0.1.0-py3-none-any.whl` с модулем плагина
и манифестом. Для сборки нужен pip и setuptools с поддержкой `bdist_wheel`
(современный setuptools включает её; для старых версий нужен пакет wheel).
Сборка использует установленное окружение и не обращается к сети.
`./build.sh -tp` сначала запускает все тесты, затем собирает плагин.
`-b` и `-a` сохраняют прежнее назначение — сборку приложения; `-p` включается отдельно.
API `ElPartsPluginApi` предоставляет приложение, в wheel плагина оно не копируется.

## Проверка

```sh
python3 -m unittest discover -s tests/kikad_plugin -v
```

Тесты импортёра, установки, процесса, записи БД и интерфейса находятся в `tests/kikad_plugin` и входят в общий запуск `./build.sh -t`.
Локальный тестовый проект хранится в `tests/input/SMHome_UniversalRound_ESP32_C3_Mini_v4`:
файл `.kicad_pro`, корневая схема и две дочерние схемы с исходными именами.
Сохранённый эталон `components.expected.json` получен из экспорта `kicad-cli`.
Основные проверки выполняются без установленного KiCad и без исходного проекта
из пользовательской директории.

Дополнительно можно выполнить сверку с новым экспортом KiCad. Экспорт создаётся
во временном каталоге, а входные файлы читаются из `tests/input`:

```sh
KICAD_CLI='/Applications/KiCad/KiCad.app/Contents/MacOS/kicad-cli' \
python3 -m unittest discover -s tests/kikad_plugin -v
```

В тестовых данных возвращаются 49 позиций: 11 резисторов, 9 конденсаторов,
9 диодов, 7 разъёмов, 4 тестовые точки, 4 прочие позиции, по одному предохранителю,
дросселю и модулю и 2 микросхемы. Полный перечень и JSON-пример:
[раскладка данных](../../docs/kicad-importer.md).

При полном запуске через `./build.sh -t` очистка временных БД и ротация бэкапов
выполняются автоматически. Правила и команды для прямого полного запуска unittest:
[проверка и очистка](../../docs/plugin-runtime.md#проверка-и-очистка-тестовых-бд).

Без `KICAD_CLI` используется `kicad-cli` из PATH. Если он недоступен,
пропускается только дополнительная проверка экспорта.
